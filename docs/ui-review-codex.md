# 語橋 Live UI Review

- 檢查方式：使用 computer use 實際操作同一個 Edge 視窗；以管理員測試帳號登入。
- 已巡覽：登入深色與亮色、開會設定與即時翻譯模式、服務狀態、浮動字幕、會議列表、逐字稿校對與播放、改字流程（取消未保存）、會議紀要、待辦看板、搜尋、問答、成效指標 `/metrics`、團隊管理、頭像更換入口、404。
- 響應式：以 Edge 視窗縮窄檢查登入亮色、開會頁、會議列表、待辦看板與校對頁；實際最窄約 500 px，未能達到約 400 px。會議、列表、待辦、校對頁均已在此寬度實際顯示。
- 安全邊界：未刪除會議或待辦、未寄送紀要、未更換/移除照片；雲端精修/精準模式維持關閉，也未啟動會議錄音。
- 截圖位置：[docs/ui-review-shots](ui-review-shots/)。
- Computer Use 在擷取窄版開會頁時中止；依工具要求停止 UI 操作。該頁已實際檢視，但本輪窄版開會頁截圖尚未保存。

## 發現（依嚴重度排序）

### 中

1. **頁面：會後校對** — 點「修改原文」後，編輯框直接佔用原文欄位，譯文欄被擠成極窄的一條，閱讀與對照原文/譯文變得困難。**建議改法：**編輯時讓逐字稿欄位獨立換行或改成明確的編輯面板；維持譯文可讀，並保留儲存與取消操作。**截圖檔名：**`transcript-edit-layout.jpeg`（待補）。
2. **頁面：開會頁／浮動字幕** — 開啟浮動字幕後，字幕視窗出現在瀏覽器右側畫面之外，只看得到被裁切的一小部分，無法讀取字幕。**建議改法：**以視窗可視範圍定位初始位置，並在拖曳/縮放後將視窗限制在螢幕內。**截圖檔名：**`meeting-live.jpeg`。
3. **頁面：會議列表** — 多筆會議共用「11/14 21:50 的會議」預設名稱及同一時間，列表又有多筆顯示「無錄音／沒有校對資料」，難以分辨正確會議。**建議改法：**優先顯示建立者、語言、系列或短識別碼等可區分資訊；對同時建立的紀錄增加辨識提示。**截圖檔名：**`meetings-list.jpeg`。
4. **頁面：開會設定／服務狀態** — 頁首顯示「服務就緒」，麥克風區同時提示「請先按『測試音源』並允許麥克風」；首次使用者不易判斷「服務就緒」是否也代表音訊已可用。**建議改法：**拆分伺服器、麥克風權限及音量狀態，並顯示每項明確的待完成步驟。**截圖檔名：**`meeting-live.jpeg`。
5. **頁面：搜尋** — 搜尋「合約 客戶」顯示 10 筆、來自 1 個來源，其中多筆是同一會議中措辭近似的待辦；相似結果佔據清單，較難快速找到逐字稿脈絡。**建議改法：**預設合併重複或近似待辦，並提供依結果類型分組/篩選。**截圖檔名：**`search-results.jpeg`。
6. **頁面：問答** — 問「誰負責把合約寄給客戶？」時，回答先稱王愛麗負責，後文又提到另一筆資料指向楊（測試）；出處中有多筆措辭相近的同源待辦。回答的主結論與分歧資料未清楚分層，容易讓人忽略責任人不一致。**建議改法：**把衝突來源和依據明確列為「資料不一致」，先呈現各來源負責人與原文，不要以「多數」掩蓋不同指派。**截圖檔名：**`qa-answer.jpeg`。
7. **頁面：團隊管理／成員操作** — 成員列的「移除照片」與「移除」按鈕相鄰且視覺樣式相同，前者清除頭像、後者移除團隊成員，結果差異大但容易混淆。頭像「更換照片」會直接開啟系統選檔視窗，未在操作前說明圖片尺寸或是否可裁切。**建議改法：**將兩種移除操作改成有明確動詞與不同視覺層級的按鈕；更換前說明支援格式、尺寸與裁切方式。未移除成員或照片，檔案選擇器已取消。**截圖檔名：**`team-management.jpeg`。
8. **頁面：響應式／導覽列** — 窄版的待辦頁首只顯示搜尋、頭像、登出與主題等控制，會議紀錄、成效指標及團隊管理沒有直接入口；使用者需要猜測品牌標誌可返回開會頁。**建議改法：**在窄版提供明確的「更多」選單或底部導覽，保留目前頁面名稱。**截圖檔名：**`mobile-transcript-review.jpeg`（窄版頁首共用導覽狀態）。

### 低

9. **頁面：開會頁／窄版設定** — 約 500 px 寬時，語音語言與翻譯語言下拉欄位的目前值被省略號截斷（如「中日雙…」「中文 ⇄ …」），難以確認所選語言。**建議改法：**調整欄位寬度或允許標籤換行，並以完整可讀文字顯示目前值。**截圖檔名：**`mobile-meeting.jpeg`（待補；畫面已檢視，擷取時工具中止）。
10. **頁面：待辦看板／窄版** — 16 件未開始事項在窄版改為長單欄，進行中與已完成區段排在清單後方；需要大量捲動才能比較不同狀態。**建議改法：**窄版加入狀態切換或可橫向切換的分欄導覽，避免長列表掩蓋其他狀態。**截圖檔名：**`mobile-actions-board.jpeg`（待補）。
11. **頁面：會議紀要** — 無紀要時摘要顯示「（尚無摘要）」且決議、待辦、待確認問題、風險區塊顯示「沒有條目」；主要「產生紀要」按鈕用途雖可理解，但空狀態沒有說明接下來的資料來源/結果會如何呈現。**建議改法：**在空狀態提供簡短說明與產生後預覽/確認流程提示。此次未按產生，避免觸發外部模型服務。**截圖檔名：**`minutes-empty.jpeg`。
12. **頁面：開會頁／校對頁** — `REAL-TIME MULTILINGUAL MEETING`、`LIVE TRANSCRIPT`、`LIVE TRANSLATION` 等英文大標籤與繁中介面並列，增加視覺語言切換；另有 `Azure`、`ASR`、`manifest.jsonl` 等技術字詞直接出現在使用流程。**建議改法：**將一般使用者可見的主標籤統一為繁中，技術名詞在首次出現時補上用途說明或移至進階資訊。**截圖檔名：**`meeting-live.jpeg`。
13. **頁面：待辦看板** — 多筆文字近似的合約寄送及自動部署待辦集中在「未開始」欄，內容差異小且同源會議標籤一致，掃描與辨認優先級較費力。**建議改法：**在卡片強化截止日期、負責人與來源會議的層次，並讓相似待辦更容易比對。**截圖檔名：**`actions-board.jpeg`。
14. **頁面：404** — 頁面同時說「連結可能已失效」或「沒有開啟它的權限」，但只提供回開會頁與會議紀錄的入口；遇到權限問題時沒有下一步說明。**建議改法：**保留不洩漏資源存在與否的訊息，同時提供聯絡團隊管理員或返回上一頁的明確協助。**截圖檔名：**`404-page.jpeg`。
