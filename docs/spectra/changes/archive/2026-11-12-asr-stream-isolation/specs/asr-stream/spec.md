## Purpose

The local ASR service streams recognition for several connections at once (meetings and live translation). This capability covers how each stream request is identified, authorized and kept isolated from other connections, so one connection can neither write files outside the service's own directories nor change another connection's speech detection.

## ADDED Requirements

### Requirement: Stream request identifier

The gateway SHALL generate a new random UUID as the `requestId` of every stream it opens to the local ASR service and SHALL NOT forward a `requestId` supplied by the browser. The ASR service SHALL accept a `requestId` only when it consists of 1 to 64 characters from `A–Z`, `a–z`, `0–9`, `-` and `_`. The ASR service SHALL check the `secret_key` and the `requestId` before it creates any file for the request; when either check fails it SHALL close the connection without creating a log file or an audio directory. Every file path the ASR service builds from a `requestId` SHALL resolve inside its intended directory (`logs/requests/` for the request log, `wav_tmp_store/` for saved audio).

#### Scenario: Browser-supplied identifier is replaced

- **WHEN** the browser starts a local-engine stream with header `requestId` `../../outside`
- **THEN** the header the gateway sends to the ASR service carries a UUID generated by the gateway, and no part of the browser's value

#### Scenario: Unsafe identifier is rejected before any file is created

- **WHEN** a client connects to the ASR service directly with a valid `secret_key` and a `requestId` that fails the format check
- **THEN** the ASR service closes the connection with an error and creates no file under `logs/requests/` or `wav_tmp_store/`

##### Example: identifier checks

| requestId | Accepted |
| --------- | -------- |
| `3f2b8c1e-9a4d-4e7b-8c2a-1d5e6f7a8b9c` | yes |
| `abc_DEF-123` | yes |
| `../../outside` | no |
| `a/b` | no |
| `""` (empty) | no |
| 65 × `a` | no |
| `id with space` | no |

#### Scenario: Wrong secret creates no log file

- **WHEN** a client connects to the ASR service with a well-formed `requestId` and a wrong `secret_key`
- **THEN** the ASR service closes the connection as unauthorized and creates no file for that `requestId`

### Requirement: Per-connection speech detection

The ASR service SHALL load the VAD model weights once and share them, and SHALL give every stream connection its own VAD stream state (feature extractor, model cache and post-processor). Audio of one connection SHALL advance only that connection's VAD state, and starting or ending a connection SHALL NOT reset or alter the VAD state of any other connection. Speech detection SHALL keep running on every chunk of every connection, whether or not the connection set `use_vad`, because the `speech_end` flag it produces is sent to the client in every result.

#### Scenario: Interleaved audio gives the same detection as separate audio

- **WHEN** two different audio signals are fed chunk by chunk, alternating between two connections' VAD states
- **THEN** each connection's sequence of per-frame detection results equals the sequence obtained by feeding that signal alone

##### Example: two signals alternating

- **GIVEN** two different 12 s speech recordings A and B, each cut into 0.5 s chunks A1..A24 and B1..B24, and both containing detected speech when fed alone
- **WHEN** chunks are fed in the order A1, B1, A2, B2, …, A24, B24, A-chunks to connection A's VAD state and B-chunks to connection B's
- **THEN** connection A's per-frame results (speech flags, probabilities, speech start and end frames) equal those from feeding A1..A24 alone, and connection B's equal those from feeding B1..B24 alone

#### Scenario: A new connection does not reset an ongoing one

- **WHEN** connection A is mid-sentence and connection B connects with `use_vad` on
- **THEN** connection A's next detection results are the same as if B had never connected
